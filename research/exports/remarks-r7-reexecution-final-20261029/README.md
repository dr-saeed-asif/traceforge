# R7 re-execution oracle

Measured additional Table 4 comparison. All 200 final workspaces are preserved and SHA-256 workspace digests checked before use. Re-execution uses a fresh workspace copy inside Linux chroot/network/mount namespaces, a separate tool UID and no inherited credentials. Node 22.14.0 is from the official checksum-verified Linux release; npm 10.9.2, Vitest 3.2.4 and pinned research pytest dependencies are provisioned. Per-claim environment and original outputs are retained. Isolated loopback is enabled for local test-runner IPC; there is no external network route.

The oracle checks final-state executability, whereas gold/TraceForge judge captured actions at claim time. Agreement is therefore not proof of equivalence: re-execution can pass an invocation that was never observed, or fail after a stale prior passing run. Do not label its agreement as ordinary verifier accuracy. Non-command claims and explicitly excluded unsafe invocations are outside the denominator; remaining environment failures/crashes/timeouts count as errors. Setup failures in earlier raw runtime attempts are retained under research/runs/remarks-r7-oracle-*; they are not substituted for final outcomes. Latencies were measured on a shared workstation and are descriptive, not clean paired overhead.
